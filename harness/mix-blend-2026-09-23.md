# mix-blend-mode (LayerEffects::with_blend) evidence, 2026-09-23

PR #355's head (fe-blend 46a3149, harness with `--cfg harness_blend`) versus
branch mix-blend (`--cfg harness_mix_blend` on top), harness
`SKIP_UNSUPPORTED_FILTERS=1 VIEWPORT_CLIP=1`, against Chromium 131
(`make_ref.py`), 460x260 pivot framing. Columns: percent of pixels beyond
the threshold / structural after a 2 px erosion.

Harness mapping: a group with `mix-blend-mode` gets a layer with the mode,
an `isolation: isolate` group a plain layer, and a scene containing a blend
group is drawn inside one page-sized layer holding the background, because
the screen cannot be read back and Chromium blends a top-level child with
the page: probed with a gray `screen` rect over the white page (renders
white; the same rect inside `isolation: isolate` renders gray). The mask
precapture returns to the target it interrupted (the page layer's store),
not the screen - restoring the screen drew the whole scene there and then
composited the white page store over it.
