# mix-blend-mode (LayerEffects::with_blend) evidence, 2026-09-23

PR #355's head (fe-blend, harness `--cfg harness_blend`) versus branch
mix-blend (femtovg/femtovg#356, `--cfg harness_mix_blend` on top), one harness
for both, `SKIP_UNSUPPORTED_FILTERS=1 VIEWPORT_CLIP=1`, against Chromium 131
(`make_ref.py`). Columns: percent of pixels beyond 8/255 / structural after
a 2 px erosion. Framings: the 460x260 pivot framing at 1x/2x/4x, and
`FRAME_W=1840 FRAME_H=1040 BOX=800 BOX_X=520 BOX_Y=120` at 1x (the whole
artwork at four times the resolution; the sheets crop it 1:1).

Harness mapping (`harness/_logos_full.rs`): a group with `mix-blend-mode`
gets a layer with the mode; a group that isolates per CSS Compositing
(`Group::should_isolate`: clip-path, `isolation: isolate`, ...) and contains
a blend gets a plain layer, so the blend sees only that group (probe
`blend-in-clip`: Chromium draws the orange unblended); a scene containing a
blend is drawn inside one page-sized layer holding the background, because
the screen cannot be read back and Chromium blends a top-level child with
the page (probed: a gray `screen` rect over the white page renders white,
the same rect inside `isolation: isolate` gray). The mask precapture returns
to the target it interrupted, not the screen. The glow idiom
(`feGaussianBlur` then `feComposite operator=over in=SourceGraphic`) draws
the blurred layer and the group sharp on top, inside the group's own
opacity layer (gemini-3-7-flash's `softGlow`).
